# Веб-фоторамка: MVP, handoff для AI-агента

## 1. Цель MVP

Одна веб-страница в браузере приставки показывает фото из папки на Raspberry Pi в случайном порядке, плавно меняя кадры через заданный интервал, без участия пользователя. Больше ничего.

## 2. Исходные данные (подтверждены пользователем)

- Приставка: Xiaomi Mi Box S 2-го поколения, mitv-afkr0, Android 11, подключена к телевизору, есть интернет и домашняя сеть.
- Браузер на приставке: Browser (Android TV), пакет com.internet.tvbrowser, версия 2.16.0.
- Результаты browser-test.html (прогон на приставке, страница открыта по HTTPS): движок Android System WebView на основе Chromium 154, 36 из 36 проверок пройдены. Доступны современный синтаксис JavaScript (async/await, ?., ??, поля классов, ES-модули, динамический import), fetch, ResizeObserver, IntersectionObserver, object-fit, filter: blur(), aspect-ratio, localStorage, WebP, Fullscreen API и Wake Lock (запрос удержания экрана выполнен успешно). Частота кадров при анимации 54 в секунду. Память устройства 2 ГБ, 4 ядра, лимит JS-кучи 527 МБ. Экран сообщается как 960 x 540 при DPR 2.
- Сервер: Raspberry Pi 4. На нём Samba share: папка с подпапками, внутри домашние фото. Приложение размещается на этой же Pi и читает папку локально.
- Язык: TypeScript (сервер и клиент).

## 3. Состав MVP

Два компонента: сервис на Raspberry Pi и одна страница-клиент.

### 3.1 Сервис
- Читает папку с фото рекурсивно, только на чтение. В папке с фото ничего не создаёт и не меняет.
- Индекс файлов строится при старте и хранится в памяти. Новые файлы появятся в показе после перезапуска сервиса.
- Порядок: список перемешивается и выдаётся по кругу, по исчерпании перемешивается заново. Один общий порядок на весь сервис.
- Для каждого кадра готовит изображение под экран приставки: уменьшает, учитывает EXIF-ориентацию, отдаёт в универсальном формате. Размер клиент сообщает сам, исходя из размера своего экрана в физических пикселях (экран приставки сообщается как 960 x 540 при DPR 2, то есть 1920 x 1080 физических пикселей; это вывод из результатов теста). Результат нигде не сохраняется.
- Клиент никогда не передаёт путь к файлу. Какой файл показывать, решает сервис.
- Битый или нечитаемый файл пропускается, берётся следующий.
- Отдаёт страницу-клиент.
- Форматы в MVP: JPEG и PNG. Остальные файлы игнорируются.

### 3.2 Клиент
- Одна страница, занимает всё окно браузера.
- Два слоя изображения с плавной сменой кадров. Пока виден текущий кадр, следующий уже загружается.
- Интервал смены задаётся параметром адреса страницы, есть значение по умолчанию.
- Фото показывается целиком, без обрезки, на тёмном фоне.
- Ошибка загрузки кадра: пропустить и перейти к следующему.
- Сервис недоступен: повторять попытки с паузой, пока ждёт, оставлять на экране последний кадр, если кадров не было, выдать сообщение. После восстановления показ продолжается сам.

## 5. Риски и подводные камни

- Браузер приставки: по результатам теста ограничений по синтаксису JavaScript и нужным веб-возможностям нет, понижать уровень синтаксиса при сборке клиента не требуется.
- Размер оригиналов: ресайз на сервисе остаётся обязательным. У приставки 2 ГБ ОЗУ (подтверждено значением deviceMemory). Тест «фото 12 МП» пройден, но использовал синтетическое изображение с малым размером файла: он подтверждает, что браузер создаёт и принимает изображение такого разрешения, а стоимость декодирования реальных крупных JPEG не проверена. Проверить на реальных оригиналах из архива и на показе нескольких кадров подряд (два слоя плюс предзагрузка).
- Задержка первого показа: кэша нет, поэтому каждый кадр готовится в момент запроса. Предзагрузка следующего кадра клиентом обязательна. Если на живой Pi задержка заметна, это сигнал к кэшу из раздела 9.
- Заставка и сон приставки: система может уйти в сон, пока страница показывает кадры. В MVP это решается настройками самой приставки, вне приложения. Возможность отключить заставку на этой модели требует проверки. Wake Lock в браузере при HTTPS работает, его использование вынесено в раздел 9.
- Полный экран: Fullscreen API в браузере есть, но требует жест пользователя; на снимках теста панель браузера занимает часть экрана. В MVP используется окно браузера; режим без интерфейса браузера, если он есть, включается вручную. Наличие и способ включения такого режима требуют проверки. Размер окна страницы зависит от панели и масштаба браузера, поэтому клиент использует относительные размеры.
- Одна Pi для Samba и приложения: нагрузка делится. Нагрузка не измерена, замер на живой Pi входит в приёмку.
- Недоступная или пустая папка: сервис пишет понятную ошибку в лог, страница показывает сообщение, бесконечного аварийного перезапуска быть не должно.
- Имена файлов и папок с кириллицей и пробелами: проверить на всех уровнях.
- Длительная работа: утечки памяти проявляются только в долгом прогоне.

## 9. После MVP

Ничего из этого списка в первой итерации не делается.

- Кэш подготовленных кадров с лимитом размера и очисткой. Нужен, если замеры покажут заметные задержки или нагрузку. Кэш размещать не на SD-карте, если есть альтернатива.
- Автоматическое обновление индекса без перезапуска.
- Очередь и ограничение числа одновременных подготовок кадров, лимиты процесса по памяти и процессору, пониженный приоритет, фоновая предгенерация кадров.
- Дополнительные форматы (HEIC, WebP) и видео.
- Аутентификация, защита доступа и публикация сервиса в интернет в это решение не входят. Защита доступа спроектирована отдельно: [access-codes-concept.md](access-codes-concept.md).
- Подпись с подпапкой и датой съёмки из EXIF.
- Режим заполнения экрана, размытый фон для вертикальных снимков.
- Фильтр по подпапке, отдельный порядок для каждого клиента.
