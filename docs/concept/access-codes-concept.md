# Доступ к фоторамке по коду: концепция

Статус: спроектировано, не реализовано.

## 1. Цель

Владелец даёт выбранным людям смотреть фоторамку: человек открывает ссылку и видит слайд-шоу. Остальные посетители фото не видят.

Заранее неизвестно, кому будет дан доступ. Поэтому доступ выдаётся в момент, когда владелец решил поделиться: он создаёт код для конкретного человека или компании и отправляет ссылку с этим кодом. У каждого кода свой срок действия: код для домашнего телевизора может быть бессрочным, код для друга — на один день. Код можно отозвать досрочно.

Защита рассчитана на случайных посетителей, а не на целенаправленную атаку. Если код со временем подберут, это допустимо.

## 2. Исходные данные (подтверждены владельцем)

- Raspberry Pi доступен из интернета только через туннель Cloudflare. Программа туннеля (`cloudflared`) работает на самом Pi как системная служба и ведёт на Nginx (порт 8082).
- Nginx на Pi обслуживает и другие сайты, поэтому остаётся в цепочке.
- Вывод `sudo ss -tlnp` на Pi: порт 3000 слушает `docker-proxy` на `0.0.0.0` и `[::]`, порт 8082 слушает `nginx` на `0.0.0.0` и `[::]`. Значит, сейчас приложение доступно со всей домашней сети в обход Nginx.
- `curl -I http://127.0.0.1:3000/health` на Pi возвращает `200 OK`.
- Владелец отправляет готовую ссылку с полным кодом. Набирать код вручную приходится редко, максимум один раз на устройстве.
- Коды хранятся в открытом виде, без хеширования.
- Хранилище кодов: JSON-файл в отдельной папке на локальном диске Pi. Переход на SQLite — позже, если понадобится.
- Создавать и отзывать коды можно только из домашней сети. Управление из интернета не нужно.
- Для всех причин отказа (код неверный, истёк, отозван) показывается одно и то же сообщение.
- Ограничения числа попыток и блокировок по адресу посетителя нет: посетитель может заходить с разных адресов, а риск подбора приемлем.

## 3. Что важно знать о текущей системе

- Туннель Cloudflare защищает Pi от прямых подключений из интернета, но не решает, кто может смотреть фото. Любой запрос к домену доходит до приложения.
- Сейчас сервер не проверяет, кто делает запрос (`src/back/main.ts`).
- `/api/catalog/folders` отдаёт любому посетителю список всех папок с именами.
- `/api/play/next` без параметра `folders` показывает весь архив. Если стереть `?folders=` из ссылки, человек увидит всё.
- Идентификатор папки и фото — это хеш SHA-256 абсолютного пути. Путь внутри контейнера известен (`/data/photos`), поэтому идентификатор папки с простым именем можно вычислить. Идентификаторы не являются секретом.
- Фото отдаются с `Cache-Control: public, max-age=3600`. Значение `public` разрешает общим промежуточным серверам (например, Cloudflare) хранить копию и отдавать её без запроса к Pi, то есть в обход проверки кода.
- Клиент получает картинку через `<img src>`. К такому запросу нельзя добавить свой заголовок, поэтому код передаётся параметром в адресе.
- Сторожевой таймер (`src/front/core/watchdog.ts`) перезагружает страницу через `window.location.reload()`, адрес со всеми параметрами при этом сохраняется. Если показ остановлен, таймер ничего не делает.
- Сейчас движок слайд-шоу при любой ошибке сервера бесконечно повторяет запросы с растущей паузой (`src/front/core/engine.ts`). Отказ в доступе должен останавливать показ.

## 4. Решение

### 4.1 Код доступа

Имена в программе: код доступа называется ключом. Тип записи `AccessKey`, хранилище `KeyStore`, папка `src/back/keystore/`, файл `keystore.json`, переменная `KEYSTORE_FILE`, адреса `/admin/keys`, параметр ссылки `?key=`. В текстах на экране для зрителя остаётся слово «код».

- Длина 8 символов. Каждый символ — печатный ASCII (коды 32–126): латинские буквы в верхнем и нижнем регистре, цифры, пробел и знаки вроде `-`, `_`, `!`, `?`. Не-ASCII (например кириллица) не допускается.
- Регистр важен: `k7mq2xab` и `K7MQ2XAB` — разные ключи. Введённое значение не меняют: не переводят регистр, не убирают пробелы и дефисы. В адресе страницы параметр `key` нужно корректно кодировать (`encodeURIComponent`), если в ключе есть служебные для адреса знаки.
- Код генерируется криптографически стойким генератором (`crypto.randomInt`) из того же набора печатных ASCII и проверяется на уникальность среди существующих.
- Почему 8, а не 6: ограничения числа попыток нет, поэтому стойкость обеспечивает только длина. Вариантов 95⁸ ≈ 6,6·10¹⁵. При 20 действующих кодах и 50 запросах в секунду подбор любого из них занимает в среднем очень долго. Код всё равно приходит готовой ссылкой.

Запись о коде:

| Поле | Значение |
|------|----------|
| `key` | 8 символов печатного ASCII, регистр как есть |
| `label` | подпись для владельца: «Мама», «Приставка в гостиной» |
| `folders` | `"all"` (весь архив) или непустой список идентификаторов папок, вложенные папки включаются |
| `createdAt` | время создания, ISO 8601 |
| `expiresAt` | время окончания действия, ISO 8601, или `null` (бессрочно) |

- Срок действия задаётся для каждого кода отдельно при создании. После `expiresAt` код недействителен, других условий нет.
- Пустой список папок не означает «весь архив». Весь архив задаётся только явным значением `"all"`, чтобы ошибка при создании кода не открыла всё.
- Отзыв кода — удаление записи.
- Истёкшие коды остаются в файле, пока владелец их не удалит. Автоматической очистки нет.

### 4.2 Что видит посетитель

Ссылка для отправки: `https://photos.vzateych.uk/?key=K7MQ2XAB`. Остальные параметры (`interval`, `w`, `h`) работают как раньше.

- **Открыл ссылку с кодом.** Окно ввода кода не появляется, слайд-шоу запускается сразу. Код из адреса важнее сохранённого в `localStorage`. Окно ввода появится, только если сервер отклонит код (см. ниже).
- **Открыл адрес без кода.** Если в браузере сохранён последний рабочий код (`localStorage`), страница использует его и тоже сразу запускает слайд-шоу. Иначе показывает чёрный экран с полем «Введите код» и кнопкой. После ввода страница переходит на адрес с `?key=...`, поэтому такой адрес можно сохранить в закладки.
- **Код верный.** Обычное слайд-шоу. Код сохраняется в `localStorage`.
- **Код неверный, истёк или отозван.** Сервер отвечает одинаково. Страница убирает с экрана последнее показанное фото, показывает «Код недействителен. Попросите новый у владельца» и поле для нового кода. Движок останавливается и не повторяет запросы. Сохранённый код удаляется из `localStorage`.
- **Срок кода истёк во время показа.** Отказ придёт на следующем запросе, то есть в течение одного интервала смены кадра.
- **Код верный, но в его папках нет фото** (например, папку переименовали, и её идентификатор изменился). Работает текущее поведение для ответа «нет фото».

### 4.3 Сервер: публичный порт

Публичный порт (3000) доступен из интернета через туннель и Nginx.

| Адрес | Доступ |
|-------|--------|
| `/` и статические файлы страницы | открыт, фото в них нет |
| `GET /health` | открыт, нужен сторожевому таймеру |
| `GET /api/play/next?key=...` | только с действующим кодом |
| `GET /api/photos/:id?key=...&w=...&h=...` | только с действующим кодом и только для фото из папок кода |
| `GET /api/catalog` | список/поиск папок; после миграции — только с `ADMIN_TOKEN` (сейчас ещё открыт как `/api/catalog/folders`) |

- Набор фото для `/api/play/next` определяется папками из записи кода. Параметр `folders` из адреса страницы больше не используется: выбор папок делается при создании кода.
- Фото вне папок кода: ответ `404`, как для несуществующего фото.
- Отказ в доступе: `401` с телом `{ "error": "access_denied" }`, одинаковым для всех причин.
- Фото отдаются с `Cache-Control: private, max-age=3600`: браузер зрителя может хранить картинку час, общие промежуточные серверы не должны.

### 4.4 Управление каталогом и ключами (тот же порт 3000)

Имена путей без слова `admin`: защита — секрет, а не префикс в адресе. Nginx и туннель менять не нужно.

Защита админских адресов: заголовок `Authorization: Bearer <ADMIN_TOKEN>`. Сравнение — через функцию постоянного времени `crypto.timingSafeEqual`. Токен не короче 32 символов. Если `ADMIN_TOKEN` не задан, эти маршруты не регистрируются (или всегда «нет доступа»), слайд-шоу для гостей работает.

| Метод и адрес | Назначение |
|---------------|------------|
| `GET /api/catalog` | список/поиск папок (`?q=` — как сейчас) |
| `GET /api/keys` | все ключи: поля записи и готовая ссылка |
| `POST /api/keys` | создать ключ. Вход: `label`, `folders`, необязательный `ttlHours`. Выход: запись и готовая ссылка |
| `DELETE /api/keys/:key` | отозвать ключ |

Страница каталога: **`/catalog`** (наследник текущего `catalog.html`). Ходит в `/api/catalog` с токеном; позже создаёт ключи через `/api/keys` вместо ссылок `?folders=`.

- `ttlHours` — срок действия в часах от момента создания, целое число больше нуля. Сервер вычисляет и сохраняет `expiresAt`. Без `ttlHours` ключ бессрочный.
- Готовая ссылка строится из `PUBLIC_BASE_URL`, например `https://photos.vzateych.uk/?key=K7MQ2XAB`.

#### Порядок внедрения (важно)

1. Добавить (или переименовать в) `GET /api/catalog` с проверкой `ADMIN_TOKEN`. Пока оставить рядом старый открытый `GET /api/catalog/folders` и `catalog.html` — **не удалять**.
2. Проверить новый адрес руками (`curl` с заголовком Authorization).
3. Открыть страницу **`/catalog`**: ввод токена, запросы к `/api/catalog`.
4. Добавить `/api/keys` (список, создание, удаление).
5. **Только после этого** удалить открытый `GET /api/catalog/folders` и старый `catalog.html`. Раньше нельзя: сломается текущий рабочий каталог.

### 4.5 Хранилище кодов

- Хранилище ключей: JSON-файл по пути из `KEYSTORE_FILE`, по умолчанию `/data/state/keystore.json`. Формат: `{ "version": 1, "keys": [ ...записи... ] }`.
- Файл читается при старте. Если файла нет, список пуст. Если файл повреждён, процесс завершается с понятной ошибкой: молча начать с пустого списка нельзя, иначе все выданные коды пропадут при следующей записи.
- Источник истины во время работы — память процесса. Файл перезаписывается при каждом создании и удалении кода.
- Запись атомарная: сначала во временный файл в той же папке, затем переименование поверх старого. Так сбой во время записи не портит файл.
- Ручная правка файла вступает в силу после перезапуска.
- Работа с хранилищем идёт через интерфейс `KeyStore`. Переход на SQLite позже: новая реализация того же интерфейса плюс одноразовый перенос записей из JSON-файла. Остальной код не меняется.

### 4.6 Развёртывание функции

Публикация порта 3000 (`"3000:3000"`) на этом этапе не меняется. Отдельный порт администратора не нужен.

- Для файла кодов подключается отдельная папка с правом записи: `./data/state:/data/state`. Папка с фото остаётся только для чтения. Владельцем папки `./data/state` на Pi должен быть пользователь, от которого работает контейнер (`USER node` в `Dockerfile`; его числовой идентификатор проверить командой `docker compose exec photoframe id`).

Новые переменные окружения:

| Переменная | Назначение | По умолчанию |
|------------|------------|--------------|
| `ADMIN_TOKEN` | пароль для `/api/catalog`, `/api/keys` и страницы `/catalog`, не короче 32 символов | нет; без него эти маршруты не работают |
| `PUBLIC_BASE_URL` | начало ссылок с ключом | нет; без него `POST /api/keys` возвращает только ключ |
| `KEYSTORE_FILE` | путь к хранилищу ключей | `/data/state/keystore.json` |

### 4.7 Отдельный этап после реализации: закрыть порт 3000 для домашней сети

Выполняется после того, как функция доступа по коду внедрена и проверена. От неё не зависит.

Сейчас порт 3000 слушает `docker-proxy` на `0.0.0.0` и `[::]`, то есть приложение доступно со всей домашней сети в обход Nginx. После внедрения кодов это не дыра (код проверяет приложение), но лишний путь лучше закрыть. Туннель работает на Pi и ведёт на Nginx, поэтому достаточно привязать порт к `127.0.0.1`. Порядок важен: сначала Nginx, потом контейнер.

1. Найти, как Nginx обращается к приложению: `grep -rn "proxy_pass" /etc/nginx/sites-enabled/`. Если там `http://localhost:3000`, заменить на `http://127.0.0.1:3000`. Имя `localhost` может превратиться в адрес IPv6 `::1`, на котором после шага 3 приложение слушать не будет, и сайт покажет ошибку 502.
2. Проверить и применить настройки Nginx: `sudo nginx -t && sudo systemctl reload nginx`. Открыть сайт: он должен работать, потому что порт 3000 пока открыт на всех адресах.
3. В `docker-compose.yml` заменить `"3000:3000"` на `"127.0.0.1:3000:3000"` и выполнить `docker compose up -d --no-build`.
4. Проверить:
   - `sudo ss -tlnp | grep ':3000'` показывает только `127.0.0.1:3000`;
   - `curl -I http://127.0.0.1:3000/health` на Pi возвращает `200`;
   - с другого компьютера в домашней сети `curl -m 3 -I http://<адрес-Pi>:3000/health` завершается отказом соединения или тайм-аутом;
   - сайт открывается по домену, рамка на приставке работает.
5. Откат: вернуть `"3000:3000"` и выполнить `docker compose up -d --no-build`.

## 5. Проверить на живой системе

- Сохраняется ли `localStorage` браузера приставки после перезапуска браузера и приставки. Если нет, на приставке нужно открывать закладку с `?key=...`.
- Nginx слушает порт 8082 на всех адресах. Для домашней сети это допустимо: код проверяет приложение. Если захочется ограничить, `listen 127.0.0.1:8082;` в Nginx и `http://127.0.0.1:8082` в настройке туннеля (не `localhost`, по той же причине, что в разделе 4.7).

## 6. Критерии приёмки

- Без кода и с неверным кодом `/api/play/next` и `/api/photos/:id` отвечают `401` с одинаковым телом.
- С кодом, ограниченным папками, нельзя получить фото из других папок (`404`).
- Истёкший и удалённый коды отклоняются так же, как несуществующий.
- Код, созданный с `ttlHours: 24`, работает 24 часа и затем отклоняется. Код без `ttlHours` не истекает.
- `GET /api/catalog` без верного `ADMIN_TOKEN` отвечает `401`; с верным — отдаёт каталог.
- Без заданного `ADMIN_TOKEN` адреса `/api/catalog`, `/api/keys` и `/catalog` недоступны для управления.
- Страница `/catalog` открывается и работает с токеном.
- Открытый `/api/catalog/folders` и `catalog.html` удалены только после успешной проверки `/api/catalog` и `/catalog` (не раньше).
- Созданный через `POST /api/keys` ключ сразу работает для слайд-шоу, удалённый сразу перестаёт работать. Оба изменения сохраняются после перезапуска.
- Повреждённый файл кодов останавливает запуск с понятной ошибкой.
- Страница по ссылке с действующим кодом сразу запускает слайд-шоу, окно ввода кода не появляется.
- Страница без кода в адресе и без сохранённого кода показывает поле ввода. При отказе страница убирает фото, показывает сообщение и не повторяет запросы.
- Фото отдаются с `Cache-Control: private, max-age=3600`.
Для отдельного этапа из раздела 4.7:

- С другого компьютера в домашней сети порт 3000 недоступен. Сайт по домену и рамка на приставке работают.

## 7. Не входит в эту итерацию

- Страница управления кодами для администратора.
- Ограничение числа неудачных попыток и блокировка по адресу посетителя. Стойкость обеспечивается длиной кода (раздел 4.1).
- Учёт времени последнего использования кода. Действие кода определяется только сроком `expiresAt`.
- Одноразовая активация ссылки с привязкой к устройству (защита от пересылки ссылки).
- Хеширование кодов в хранилище.
- Управление кодами из интернета (через частную сеть вроде Tailscale).
- Продление срока действия кода через интерфейс администратора (пока: удалить и создать новый).
- Автоматическая очистка истёкших кодов.
- SQLite вместо JSON-файла.
