## Исключение битых фото на сервере.

### Handoff: Вынос конфигурации интервала на бэкенд

**Цель**: Позволить управлять временем смены кадров через .env файл без необходимости пересборки фронтенда и изменения URL-адреса.

 Текущая проблема:
 Значение по умолчанию (10с) захардкожено в JS-коде фронтенда. Изменение требует полного цикла: правка кода → build → docker build → deploy.

 Предлагаемое решение:
 1. Backend (Config): Добавить переменную DEFAULT_INTERVAL_MS в .env и интегрировать её в src/back/config/env.config.ts.
 2. Backend (API): Реализовать эндпоинт GET /api/config, который будет возвращать текущие настройки сервера (включая defaultIntervalMs).
 3. Frontend (Init):
     - Модифицировать main() в src/front/main.ts, чтобы перед запуском SlideshowEngine он запрашивал конфигурацию с сервера.
     - Передать полученное значение в getConfigFromUrl в качестве базового (fallback).
 4. Приоритеты (Hierarchy of Truth):
     - URL parameter (?interval=...) → Самый высокий приоритет (для тестов).
     - Server Config (/api/config) → Средний приоритет (основной рабочий режим).
     - Hardcoded fallback (10s) → Самый низкий приоритет (на случай недоступности API).

 Результат: Смена интервала для всей системы будет осуществляться простым изменением одной строки в .env и перезапуском контейнера.

## Загружать следующий кадр сразу после показа текущего, параллельно с интервалом.
**Проблема.** Реальный интервал равен заданному плюс время загрузки на Pi, и пропуск битого кадра заметен как лишняя пауза.
**Идея.** Загружать следующий кадр сразу после показа текущего, параллельно с интервалом. Показывать по истечении интервала, если он готов, иначе как только догрузится. Если загрузка упала, пробовать другой id в остатке того же интервала.
Что учесть:
prefetch() возвращает { ok, frame | error } и не отклоняется, иначе получится необработанный rejection, пока цикл спит;
висящую загрузку нужно отменять при stop(), backoff и рестарте через AbortSignal запуска;
разделить состояния «показан / грузится / готов» или грузить в отдельный new Image();
сохранить текущие гарантии: один цикл, дедлайн на кадр, decode(), backoff, getLastProgressAt() для сторожевого таймера.
Код: engine.ts (runLoop, loadAndShowNext), layer-manager.ts. Сторожевой таймер от схемы не зависит.
